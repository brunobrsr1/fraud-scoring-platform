# ADR-002 — Production Deployment Target

**Status:** Accepted

## Context

The target system contains horizontally scalable inference nodes, a small Raft registry cluster, and a load balancer between clients and inference nodes. The deployment environment must therefore support multiple independent processes, reproducible infrastructure, and failure testing without introducing unnecessary platform complexity.

Kubernetes provides strong orchestration, service discovery, and deployment capabilities, but adopting it as the production platform would introduce a substantial additional system to operate and reason about. Those capabilities are not central to the project's main problem of model serving, registry semantics, and distributed consensus.

## Decision

Production deployment will target AWS using:

- EC2 for compute instances;
- Docker for packaging and running services;
- an Application Load Balancer (ALB) for inference traffic;
- Terraform for reproducible infrastructure provisioning.

Kubernetes may be used for local development or experimentation, but it is not a production architectural dependency.

The production topology will keep inference nodes horizontally scalable while running the Raft registry as a small, explicitly managed cluster. Infrastructure configuration will remain separate from application code and will be reproducible through Terraform.

## Consequences

This deployment model keeps the production environment relatively explicit and allows the project to demonstrate networking, process isolation, load balancing, infrastructure-as-code, and failure behaviour without making Kubernetes itself part of the problem being solved.

The trade-off is that EC2-based deployment requires more manual infrastructure management than a managed Kubernetes platform and provides fewer built-in orchestration features. Scaling, instance lifecycle, and some operational concerns therefore remain the project's responsibility.

This is an intentional trade-off: the deployment platform should provide the infrastructure needed to exercise the distributed system without becoming the primary subject of the project.
